The cross-origin-redirect corpus asks whether a provider call re-sends its request when the configured endpoint redirects to a different scheme, host or port. Every row gets its own raw TCP loopback servers, and every observation is read off them: how many requests reached the endpoint, whether anything reached another origin, and whether the row's synthetic key appeared in any byte another origin received. `agrees` is derived from all three columns.

Run `node tools/cross-origin-redirect.mjs php --check`, then repeat with `ts` and `py`. `--record` explicitly rewrites one native column. `PRISM_PHP_SRC` points the PHP adapter at a prism checkout, as in per-call-url-guard; `PRISM_TS_DIST`, `PRISM_PY_SRC`, `PRISM_PHP_BINARY` and `PRISM_PY_BINARY` work as in credential-scope. `CROSS_ORIGIN_REDIRECT_CASES` reads a different copy of the corpus, for a negative control against unchanged code.

The error each SDK raises is outside the contract; `contract.mjs` refuses any observation field but `endpoint_requests`, `reached_elsewhere` and `credential_elsewhere`. Environment names are fixed in `environment-names.json` and isolated per row. Each adapter refuses every connection that is not to a 127.x literal: PHP with a global HTTP middleware, TypeScript by wrapping `fetch`, Python by refusing DNS and sockets.
