# Harness coexistence fixture (development)

`coexistence-cases.json` is one input contract for PHP, TypeScript and Python.
`coexistence-corpus.mjs` runs all three native fixture applications and checks
each answer with `coexistence-oracle.mjs`. Native offer order and error details
are retained; the oracle compares the authority sets without rewriting them.

Every one of the six Charlotte/support/ACP boot orders must resolve only its
own providers, offer exactly its declared mode tools, execute one positive
handler, and refuse omitted, legacy and foreign tools before a model request
or handler. Inspection must match the model offer with no handler, model/provider
request, new session/thread/index entry or logical state change. Ordinary store
reads may physically purge already-expired values. The fresh-state rows here
measure zero writes; real expired and live-value controls run in each runtime's
owned-registry suite. PHP uses an explicitly asserted SQLite memory connection;
the ports use new owned directories and synthetic clients. No live credentials
or consumer applications are used.

Set the fixture paths `PRISM_HARNESS_AUTOLOAD`, `PRISM_HARNESS_PHP_RUNNER`,
`PRISM_HARNESS_TS`, `PYTHONPATH`, `PRISM_COEXIST_WORK` and
`PRISM_COEXIST_OUTPUT`; optionally set `PRISM_PHP_BINARY` and
`PRISM_PYTHON_BINARY`. The PHP output path must not already exist. Then run
`node tools/harness-coexistence/coexistence-corpus.mjs` from this repository.

The fixture also refuses static/factory/provider collisions with exact owner
diagnostics and preserves a typed participant's bound actor through a child
handoff without resolving its adapter again. Default typed construction still
requires a registered adapter.

`coexistence-sabotage.mjs` takes the same runtime paths and a new work directory.
It copies production code into that directory, then independently removes
collision and namespace guards, injects an unlisted tool, discards the inherited
actor, or bypasses the call policy in each language. It also removes the named
child-input guards from the ports. Every declared mutation must reach the intended
oracle refusal; syntax/import/setup failures do not count. The other two ports
must remain safe in every run, and original source hashes must stay unchanged.
Per-run native reports, mutated code hashes and logs are retained.

The approval control records a known approval id in another agent's thread at
the same owner/scope. Its decision and source request must stay invisible across
that boundary; neither foreign resumption nor the unanswered source call may
run the handler. A separate approval in its own source session must run once.
PHP uses its real OpenAI handler over intercepted synthetic HTTP for this test;
a prepared response fake would skip the approval machinery being checked.
The ports use synthetic model clients. No request leaves the fixture.

Named child tools reject actor/mode/scope/agent extras before creating a child,
writing storage, spending a step or requesting a model. The child policy controls
revoke permission before offering or after offering, require zero denied handlers,
and retain an authorized positive call. PHP invokes the child's actual offered
wrapper for the call-policy check; the ports exercise their runtime child loops.
Their native outcome/accounting differences are retained.

The explicit legacy extra-actor row retains an existing divergence: PHP's tool
schema refuses the extra argument without a child/model call; TS/Python ignore
it and run the child under the original actor A. A task-only positive child in
each language proves the legacy setup works. The oracle checks each native
answer and actor binding independently; it does not normalize this difference
into agreement. Master tracks the behavior change for a later minor release.

`ci.mjs` runs address, paged-index, authority, real production-mutant, live-expiry,
recovery-race, mixed-index and frozen published-old-worker groups. Each group
must exit successfully and produce its complete native evidence. `runtime-refs.json`
binds the reviewed source commits. The reusable `harness-runtime.yml` runs this
on Linux, macOS and Windows, after alignment and the pinned organization allowlist
checks for all three runtime dependency manifests. Logs and native receipts are
retained as workflow artifacts. The ninth group downloads integrity-pinned TS0.9.2
and Python0.4.2 artifacts, checks all 60 built TS and 31 Python runtime files against
those reviewed release commits, and executes seven native fixture groups directly
against those artifacts. It also exercises the explicit strict legacy options,
named mode ceiling and all five callback/waiter regressions. The two published
runtime inventories must remain unchanged throughout. PHP uses its pinned0.20.1
source and fixture dependencies; fresh normal Packagist0.19.0/0.20.1 acceptance
remains a separate recorded proof.

On Windows the published group also forces a sharing denial on an owned test
barrier. The worker must remain live, retry within its original deadline, and
accept the release only after it can read and validate the nonce. This fixture
retry does not apply to production lock records. The initial sharing failure and
its controlled red/green reproducer are retained separately from lock evidence.

The published0.9.0/0.4.0 explicit narrowing failures remain in the release evidence.
This suite requires the corrected0.9.2/0.4.2 artifacts to pass those same controls;
source cannot substitute for a published artifact or reduce the required proof.

`record-addresses.mjs --write` records expected address rows by executing the
explicitly selected, clean, pinned PHP reference. It first checks the separately
approved tuple/hostile contract and refuses disagreement; it cannot silently bless
a changed answer. Without `--write` it only checks and reports the native capture.

The published-old-worker group also compares frozen requests/stored bytes and
fourteen public legacy-default behaviors per port against the integrity-pinned
TS0.8.0 and Python0.3.0 artifacts. It retains their different empty-list behavior
and each language's native registration precedence. Named authority and explicit
strict legacy opt-ins remain separate from these default compatibility checks.

This is tranche1–2 source evidence. Builtin replacement is deferred;
mode replacement/omission remains the way to exclude a builtin, and collisions
still refuse. Canonical File lock acceptance, artifact installs and the later
attribution/erase/task-ceiling tranches remain separate requirements.
