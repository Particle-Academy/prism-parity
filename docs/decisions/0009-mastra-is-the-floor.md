# 0009 — Mastra is the floor, not the target

**Status:** accepted, 2026-08-25

## The correction

The four package specs were written from a gap analysis against Mastra. That
analysis is still the right map of what is missing, but it framed the goal as
*catching up*, and catching up is not the goal.

**Mastra is the baseline. The target is to exceed it** — on quality, on
performance, and on feature set, supporting the current state of agentic LLM
and ML operations rather than the state a competitor shipped against.

This matters because a gap-filling frame produces gap-filling work: a feature
list matched item for item, each item built to the standard of "present".

## What exceeding actually means

Not a longer feature list. Three specific things.

### Quality — where the advantage already exists

This ecosystem has a discipline that most do not, and it was expensive to
acquire. Conformance corpora generated by executing the reference. Discrimination
probes with exact failure sets. Guards that must be watched failing before they
are trusted. Documented gaps recorded in the manifest so a green tick is never
over-read.

Every one of those came from a real defect, and several came from defects in
this ecosystem's own packages. The advantage is not that we write fewer bugs —
it is that we find them before a consumer does, and say so when we have not.

**A package that ships its own adversarial suite is evidence. One that claims a
property is a claim.** That distinction is the differentiator, and it is
available to every package here.

### Performance — a requirement, not an optimisation

An AI backbone sits in the hot path of every request an agentic application
makes. Latency added here is paid on every turn, forever.

The specific traps, all of which have bitten someone:

- **Retrieval that is O(everything).** A memory or corpus layer whose cost
  grows with total stored content rather than with what is retrieved.
- **Synchronous work on write.** Embedding during `remember()` makes each turn
  pay for the last one's bookkeeping.
- **N calls where the provider accepts a batch.** Prism's embeddings surface
  takes an array; using it one item at a time is a self-inflicted N× latency.
- **Defeating provider-side prompt caching.** Anthropic and OpenAI both price
  cached prefixes differently, and anything that reorders context invisibly
  makes a request more expensive while appearing to make it cheaper. Prism
  already tracks `cacheWriteInputTokens` and `cacheReadInputTokens`; a package
  that ignores them can regress cost with no visible signal.

A benchmark showing behaviour against scale is worth more than a paragraph
claiming it scales.

### Feature set — current, not contemporaneous

The bar is what agentic systems need now, which moves. Things worth being ahead
of rather than behind:

- token-budget-aware retrieval, rather than a fixed *k* that ignores whether
  the result fits the caller's context window
- recency and relevance as separate, caller-weighted axes — pure similarity
  returns the most similar thing, not the most useful one
- prompt-caching awareness as a first-class concern
- treating remote tool descriptions and results as untrusted instructions,
  because they are

## The failure mode this guards against

The obvious way to lose is to match a competitor's feature list and be worse at
each item. The subtle way is to add features nobody asked for because a
competitor had them — which is why
[specs/README.md](../specs/README.md) records a workflow engine as
*deliberately not built* despite Mastra having one.

Exceeding is not the same as covering more surface. It is being better at the
surface that matters, and honest about the surface that does not exist yet.
