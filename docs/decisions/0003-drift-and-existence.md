# 0003 — Drift and existence are different mechanisms

**Status:** accepted, 2026-08-25

## The limitation that shapes this repository

**A conformance corpus guards DRIFT, not EXISTENCE.**

A fixture table takes two implementations, runs the same rows against both, and
reports that they disagree. It cannot fail on absence, because a missing mirror
has nothing to run the rows against. A resolver that exists in PHP and has no
TypeScript twin can sit there for months, and no amount of conformance will
notice — there is nothing to compare.

So this repository ships **two mechanisms**, and they are not variations of each
other.

## 1. Drift — `suites/`

Language-agnostic rows, executed by every implementation, compared byte-for-byte.

- Goldens are GENERATED by running the reference, never hand-authored. See
  [0006](0006-goldens-from-the-reference.md).
- Every row states what it exists to catch. A case without a stated purpose gets
  deleted by someone later who cannot tell it apart from its neighbour.
- Every suite declares which implementations run it and what each one does NOT
  cover, so a green tick is never over-read.
- Every suite is backed by discrimination probes: a faithful control that must
  pass everything, plus mutants that must each fail an EXACT set of case ids.
  Without the mutants the table is decoration; without the control the mutants
  prove only that the port is broken.

## 2. Existence — `manifest/packages.json` + `tools/parity-check.mjs`

A registry of what exists, in which language, at what version, with what surface.

Two lists do the work:

- **`mirrors`** — units we have COMMITTED to keeping in step. A mirror missing
  from a language that requires it is a BUILD FAILURE. This is the check a
  fixture table structurally cannot perform.
- **`deferred`** — units present in the reference that the ports deliberately do
  not have yet, each with a reason. This is what lets the drift report tell a
  decision apart from an oversight: a listed absence is the plan, an unlisted one
  is drift.

`tools/parity-check.mjs` **discovers** the languages in play — from the loader
directories, the runner directories, and the `implementations` block of every
suite manifest — and fails when it finds one the manifest does not list.

That discovery is deliberate and it is the whole point. A hand-maintained list of
languages is the same failure one level up: add a fourth port, forget the
manifest entry, and the check that exists to catch exactly that omission is the
thing that misses it. Any check for duplicate-value drift must enumerate the
copies from a single source.

**Vacuity guards.** Every discovery in this repository fails when it finds
nothing. A check that silently passes over an empty set is indistinguishable from
one that works, and strictly worse than not having it — it produces a green tick
that means nothing.

## And the third thing, which is neither

Neither mechanism enforces **methodology parity** — the claim that an agent who
learned Prism's patterns in PHP can build the same application in TypeScript.

Fixtures pin behaviour at the boundary. They say nothing about whether the two
packages *teach* the same model. That is a documentation and API-shape problem,
and what enforces it is having ONE place where each pattern is described, with
every port's documentation POINTING at it rather than restating it.

Restated documentation drifts exactly like restated code, and nothing tests
prose. So `docs/patterns/` lives here, and `prism-ts` and `prism-py` link to it.

## Make it fail on purpose once

Every check in this repository was verified by breaking the thing it guards and
watching it go red, before being trusted.

A green assertion nobody has seen fail is a hypothesis, not a test. The failure
mode is not theoretical: a repository elsewhere carried a test asserting its own
four version declarations agreed, and it was red — two had drifted two releases
behind — in the repository whose entire argument is that unchecked duplicates
drift. **Do not let a red test sit.** A red test nobody fails the build on is a
comment.
