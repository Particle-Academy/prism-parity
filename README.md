# prism-parity

Parity control for [Prism](https://github.com/Particle-Academy/prism) and its
language ports.

This repository answers one question mechanically: **has a port fallen behind?**

It answers it two ways, because one is not enough.

| | Mechanism | Catches | Fails the build when |
|---|---|---|---|
| **Drift** | `suites/` — a conformance corpus every implementation runs | Two implementations quietly disagreeing | A port produces different bytes from the reference |
| **Existence** | `manifest/packages.json` + `tools/parity-check.mjs` | A mirror that was never built at all | A committed mirror is missing from a language that requires it |

A conformance corpus **cannot** catch the second. A fixture table compares two
implementations and reports that they disagree; it can never fail on absence,
because a missing mirror has nothing to run the rows against. That limitation is
the reason this repository ships two tools rather than one, and it is written up
in [docs/decisions/0003](docs/decisions/0003-drift-and-existence.md).

> **Working on this package?** Read **[`AGENTS.md`](AGENTS.md)** first — the boundary
> this package has to hold, the gates that must be green, and the traps that have
> already caught someone.
> `@link AGENTS.md`

## Layout

```
VERSION                     the fixture set's own semver — printed by every runner
manifest/packages.json      what exists, in which language, at what version
suites/<id>/manifest.json   what a suite pins, which language is the REFERENCE,
                            every implementation that runs it and what it misses
suites/<id>/cases.json      the rows
schema/                     JSON Schema for both of the above
probes/probes.json          the discrimination probes: a control plus mutants
parity/ledger.json          which runners are cross-checked, and the known gaps
runners/README.md           how to write a runner; the subprocess CLI contract
runners/php/                the reference runner
loaders/{php,ts,py}/        one loader per language — each SHIPS THE FIXTURES
                            INSIDE ITS OWN ARTIFACT
scripts/cross-check.mjs     runs every runner, requires IDENTICAL VERDICTS
tools/                      golden generation, corpus guards, the parity check
docs/patterns/              the canonical pattern documentation the ports LINK to
docs/decisions/             why this is shaped the way it is
```

## The corpus today

The corpus began with one core vertical slice. The coordinated launch target is
larger: core plus every reusable shipping satellite in PHP, TypeScript and
Python. `manifest/packages.json` records that package-family matrix and
`tools/parity-check.mjs --report` prints its remaining gaps. See
[decision 0021](docs/decisions/0021-parity-is-the-shipping-library-set.md).

Corpus `0.1.0`. Five suites, 49 cases.

| Suite | Kind | Cases | Pins |
|---|---|---|---|
| `openai-text-request` | request-payload | 28 | The OpenAI Responses request body |
| `openai-text-response` | response-parse | 7 | Parsing a response into a result |
| `value-object-roundtrip` | roundtrip | 9 | Value objects through storage and back |
| `text-errors` | error-code | 3 | Which failure a misuse produces |
| `json-container-identity` | container-identity | 2 | What each language's parser can tell apart |

Goldens are **generated by executing the reference**, never hand-authored. See
[docs/decisions/0006](docs/decisions/0006-goldens-from-the-reference.md).

## Running it

```sh
# reference runner
cd runners/php && composer install && cd ../..
php runners/php/runner.php

# regenerate goldens against the released reference, then verify they are current
php tools/generate-goldens.php
php tools/generate-goldens.php --check

# ship the fixtures into each loader package, and verify the copies are current
node tools/sync-corpus.mjs
node tools/sync-corpus.mjs --check

# corpus invariants, existence check, drift report
node tools/guard-corpus.mjs
node tools/parity-check.mjs --report

# loaders
cd loaders/ts && node --test test/
cd loaders/py && python -m pytest tests

# every runner, identical verdicts
node scripts/cross-check.mjs
```

## Rules that carry the weight

Each of these exists because of a real silent failure, here or in a sibling
project. They are not style preferences.

1. **Loaders load fixtures from the PUBLISHED package, never a sibling
   checkout.** Each loader ships the corpus inside its own artifact and finds it
   by walking up from its own file. A hard-coded `../../` works in exactly one
   directory layout and silently no-ops everywhere else — including CI, which
   checks out one repo.

2. **Assert CODES, not messages.** Errors are worded idiomatically per language.
   Pinning prose holds every implementation to a translation and goes red on a
   wording improvement that changed nothing.

3. **Discrimination probes, or the table is decoration.** A faithful **control**
   that must pass everything, plus mutants that must each fail an **exact** set
   of case ids — not "at least one". Without the control the mutants prove only
   that the port is broken.

4. **A skip is a MAP keyed by language, and its reason is mandatory**, enforced
   at load time in all three loaders and pinned from both directions. A loader
   that reads the skip as a truthy scalar skips every language at once *and*
   makes the blank-reason guard unreachable, because a non-empty map is never
   blank — both effects silent, both builds green.

5. **Case ids are never renumbered.** They appear in other repositories' skip
   lists and in `probes/probes.json`. Ids are unique **and** sorted, which is why
   a new case goes at the **end** of the file: file order is not chronology.

6. **Every case states what it exists to catch.** A case without a stated purpose
   gets deleted by someone later who cannot tell it apart from its neighbour.

7. **Exact by default; tolerance is per-row and declared.** There is no global
   float epsilon. A global tolerance is invisible, and an invisible one lets two
   implementations that computed different values pass as equal.

8. **Every loader's own assertions run against the SHIPPED corpus**, or a
   deliberately corrupted copy of it — never hand-written example rows. A loader
   can assert something the reference language cannot express, and no amount of
   green ticks will surface it.

9. **Make it fail on purpose once, before you trust it.** Every check here was
   verified by breaking the thing it guards and watching it go red. A green
   assertion nobody has seen fail is a hypothesis.

10. **Anything that discovers has a vacuity guard.** A check that finds nothing
    fails rather than passes. Silently succeeding over an empty set is
    indistinguishable from working.

11. **Do not let a red test sit.** A red test nobody fails the build on is a
    comment — in the repository whose entire argument is that unchecked
    duplicates drift.

## Findings

What building the ports surfaced about the PHP package. These are the most
valuable output of this work; several are live defects.

### F-1 — Failures are identified by an English sentence and nothing else

`PrismException` carries no code. The only way to tell "prompt and messages were
both set" from "the provider returned an error" is to match on prose. Every
consumer that needs to branch on a failure is therefore string-matching, and
**every wording improvement is a silent breaking change for them**.

This is visible inside this repository: the PHP runner's verdict on the
`text-errors` suite is reached by `str_contains` on message text, in a suite
whose argument is that prose is not the contract. The shim is
`runners/php/src/Driver.php::errorCode` and is marked as one.

**Suggested change.** Give `PrismException` a `code` (`prompt_and_messages`,
`malformed_tool_call_arguments`, `unsupported_provider_action`,
`provider_response_error`, …) set by each named constructor. Additive, no
behaviour change, and it lets consumers stop parsing English. Both ports already
do this.

### F-2 — A falsy prompt is silently dropped, and slips past its own guard (live defect)

`Text\PendingRequest::toRequest()`:

```php
if ($this->messages && $this->prompt) {
    throw PrismException::promptOrMessages();
}
// …
if ($this->prompt) {
    $messages[] = new UserMessage($this->prompt, $this->additionalContent);
}
```

Both tests are truthiness tests, so a prompt that is exactly `"0"` — or `""` —
fails **both**:

- it is never appended, so the request goes out with **no user message at all**;
- and it does not trip the prompt-versus-messages refusal, so a caller who set
  both gets a **successful call that answered a different question**.

The corpus found this on its first run: `trq-0022` produced `"input":[]`.

This is the same class of bug as commit `0f4e8ae`, *"stop `array_filter()`
dropping message content that is exactly `0`"* — that fix reached the provider
message maps and **missed the entry point**.

Pinned by `trq-0021`, `trq-0022` and `err-0003`, whose goldens encode the correct
behaviour and which are skipped for PHP until the reference agrees.

**Suggested change.** `!== null` in both places, or `Payload::compact()`-style
handling consistent with the fix already made downstream.

### F-3 — PHP's single array type makes `toArray()` output ambiguous

```php
json_decode('{}', true) === json_decode('[]', true)   // true
json_encode([])                                        // "[]"
json_encode(['a' => 1])                                // "{\"a\":1}"
```

A map-typed field — `AssistantMessage::$additionalContent`,
`UserMessage::$additionalAttributes`, `ToolResult::$args` — serialises as an
empty **array** when empty and as an **object** when populated. The same field
changes JSON type with its contents, and no consumer in another language can
reproduce that without modelling maps as arrays throughout.

The reference already works around it at the send boundary, with
`?: (object) []` guards duplicated across **eight** provider message maps. A
ninth provider added without that guard would send `[]` for an empty tool-call
argument set and be rejected — and nothing would catch it.

**Suggested change.** Cast map-typed fields to objects in `toArray()`, and lift
the eight duplicated guards into one helper beside `Providers\Support\Payload`.

### F-4 — The value objects are write-only

`prism` has `toArray()` on every message and no `fromArray()` anywhere.
Searching `src/` for reverse mapping turns up only `Embedding::fromArray` and
`ModerationResult::fromArray` — nothing for messages, no casts, no hydration.

That gap is not academic. It forced `prism-harness` to invent its own
`MessageMapper` and `ValueObjectMapper`, and that invention shipped a defect on
2026-08-25 (`4515281`) which **corrupted every stored Anthropic assistant
message**: `additionalContent` was stored raw, JSON turned a
`MessagePartWithCitations` into an array, and it came back as one — failing on
the *next* provider call, inside a mapper, naming a class the application never
mentioned.

A package that can write a conversation and cannot read it back pushes that
problem onto every consumer, and each of them will solve it differently.

**Suggested change.** Ship `fromArray()` beside `toArray()` on the message value
objects. Both ports do, and `value-object-roundtrip` pins it — with PHP recorded
as unable to run the rehydration half.

### F-5 — The 2^53 boundary (a port limit, recorded here so it is not lost)

JavaScript cannot represent integers above 2^53 and **cannot detect that it
cannot**: `JSON.parse('{"id":9007199254740993}').id === 9007199254740993` is
`true` in Node. PHP and Python are both exact.

Nothing in the corpus carries such a value today — provider ids are strings,
timestamps are seconds — and `tools/guard-corpus.mjs` keeps it that way by
scanning the case files **as text**. A provider adopting snowflake ids would walk
straight into it, and `prism-ts` is the implementation that would round silently.

### F-6 — `UserMessage`'s constructor mutates its own input

```php
public function __construct(public readonly string $content, public array $additionalContent = [], …)
{
    $this->additionalContent[] = new Text($content);
}
```

The stored `additionalContent` therefore already contains a text part built from
`content`. Handing it back to the constructor appends a **second** copy, and the
message text doubles on every save-and-load cycle. Nothing errors; the
conversation just grows. `prism-harness` has to strip the trailing part
explicitly, and both ports had to do the same.

Pinned by `rtp-0001` and by the `rehydrate-reappends-text` probe.

**Suggested change.** Build the parts list in a named constructor rather than
mutating a promoted property, so the value object is idempotent under round trip.

### F-7 — Two filters that disagree inside the same payload

`BuildsRequestBody` uses `Arr::whereNotNull`; `ToolMap` uses a bare
`array_filter`. So in one request body, `store: false` **is** sent and
`strict: false` **is not**. Both are pinned (`trq-0016`, `trq-0010`) because a
port has to reproduce them, but the inconsistency is the reference's.

The same `array_filter` means a tool literally named `"0"`, or one with an empty
description, silently loses those keys. Nothing pins that and nothing would catch
it.

### F-8 — Response parsing can fatal instead of raising a Prism exception

`Handlers\Text::addStep` passes `data_get($data, 'usage.output_tokens')` — no
default — into `Usage`'s non-nullable `int`, and `data_get($data, 'id')` into
`Meta`'s non-nullable `string`. A provider response missing either dies with a
PHP `TypeError`, not a `PrismException`, so a caller's `catch (PrismException)`
does not see it.

### F-9 — Smaller things, found while porting

- `ProviderTool` has no `toArray()` while every sibling value object does — it
  simply cannot be serialised by the reference.
- Nested tool-call `arguments` are re-encoded with PHP's **default** `json_encode`
  flags, so a tool argument containing `/` or non-ASCII becomes `\/` and
  `\uXXXX` *inside* the arguments string while the outer document escapes
  neither. No case pins it today.
- `Step::toArray()` builds `reasoningSummaries` with `->filter()->toArray()` and
  runs `array_map` over an `array_filter`ed output list. `filter()` preserves
  keys, so a gap makes `json_encode` emit a JSON **object** where an array is
  intended.
- `Tool::description()` reads an uninitialised typed property when `for()` was
  never called, which is a PHP `Error`.
- `Providers\Provider::stream()` passes `__METHOD__` to
  `unsupportedProviderAction` where every sibling passes a short verb, so that
  one message reads with a fully-qualified class name — exactly the kind of
  inconsistency F-1's prose-matching shim trips over.
- Message-level `providerOptions` are silently dropped by `prism-harness`'s round
  trip, and `ValueObjectMapper::encode()` captures only public properties, so a
  `Media` reaching an assistant message's additional content rebuilds without its
  file id or storage path.
